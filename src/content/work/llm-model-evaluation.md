## 배경

캐릭터 대화 게임에서 대화 모델을 고르는 일은 비용과 캐릭터다움을 함께 정하는 일입니다. 후보 모델들의 성능과 가격을 같은 기준으로 비교해 보고해야 했습니다.

## 평가 설계

캐릭터 「제키」를 기준으로 삼아, 다섯 가지를 확인 포인트로 정했습니다.

- 말투
- 감정
- 세계관
- 관계
- 캐릭터 이탈 감지

이를 바탕으로 6개 항목을 별점으로 매겼습니다.

- 말투 일관성
- 감정 깊이
- 세계관 정합성
- 관계 표현
- 캐릭터 능동성
- 응답 길이 적절성

## 후속: 대화 품질 문제를 원인까지 추적

### 화자 혼입

모델이 캐릭터 대사 뒤에 **사용자 대사까지 지어내는** 문제가 있었습니다.

1. 오프라인에서 3개 사례로 재현했습니다.
2. 원인을 찾았습니다. 대화 기록을 대본처럼 이어 붙인 텍스트 하나로 user 메시지에 넣으면, 모델이 대본을 이어 쓰는 작업으로 받아들였습니다.
3. 고쳤습니다.
   - 공통 LLM 클라이언트에 턴 구조를 추가했습니다.
   - OpenAI·Anthropic·Gemini 클라이언트가 각자의 역할 형식(Gemini는 `model`)으로 변환하게 했습니다.
   - 출력 형식 지시문은 system instruction 끝으로 옮겼습니다.

![수정 전에는 대화 기록을 「캐릭터: …」「사용자: …」 대본 텍스트로 이어 붙여 user 메시지 하나에 넣었고, 모델이 대본을 이어 쓰며 사용자 대사까지 지어냈다. 수정 후에는 user와 assistant 턴이 번갈아 쌓인 메시지 목록으로 넘겨 캐릭터 대사만 출력한다. 공통 LLM 클라이언트가 공급자마다 역할 형식으로 바꾸고(Gemini는 model), 출력 형식 지시문은 system instruction 끝에 둔다.](/image/work/llm-model-evaluation/speaker-mixing.svg)

### 반복 문장

캐릭터가 같은 문장을 되풀이하는 문제에는 저장 전 필터를 넣었습니다.

1. 응답을 문장으로 나눕니다.
2. 15자 이상인 문장을 과거 응답과 유사도로 비교합니다.
3. 유사도 0.7 이상이 2회 이상 나오면 그 문장을 뺍니다.
4. 남는 분량이 원문의 30% 미만이면 원문을 그대로 둡니다.

LLM에 다시 넣는 대화 기록에도 같은 필터를 씁니다.

### 지문 섞임과 결함 분류

3인칭 지문과 영어 행동 문장이 섞이는 문제를 따로 다뤘습니다.

- 평가표에 치명적 결함 5유형을 추가했습니다.
- 지표에 평균 외 최저점과 결함률을 더했습니다.

새 모델(Claude Haiku 5.5)로 바꾼 당일 답장에 지문이 섞이는 것을 보고, 원인을 찾기 전에 먼저 이전 모델로 되돌렸습니다. 그다음 일상 질문 34개를 추론 강도·캐릭터·호감도 조건별로 돌려 문제가 특정 캐릭터의 특정 호감도 지시문에서만 생긴다는 것까지 좁혔습니다.

## 한계

- 평가 표본이 작습니다 (캐릭터 1명, 평가자 1명, 질문 수 기록 없음).
- 화자 혼입과 반복 문장 수정 뒤, 실서비스에서 발생률이 얼마나 줄었는지는 측정하지 못했습니다.
