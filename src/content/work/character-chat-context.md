## 배경

「멸망한 세계의 신이 되었다」와 「비정규직 황후」는 플레이어가 LLM 캐릭터와 대화하며 스토리를 진행하는 모바일 게임입니다. 「멸망한 세계의 신이 되었다」는 팀이 2025년에 [Google Play](https://play.google.com/store/apps/details?id=com.dobbycanvas.verdandi)와 [App Store](https://apps.apple.com/kr/app/id6741012872)에 출시했습니다. 「비정규직 황후」도 [Google Play](https://play.google.com/store/apps/details?id=com.dobbycanvas.empress)와 [App Store](https://apps.apple.com/kr/app/the-irregular-empress/id6760219847)에서 받을 수 있습니다.

이런 게임에서는 세 가지가 계속 문제가 됩니다.

- **무엇을 프롬프트에 넣을까.** 캐릭터 설정은 많고, 호감도와 스토리 진행에 따라 지금 알아야 할 것과 아직 알면 안 되는 것이 달라집니다.
- **LLM API는 실패한다.** 빈 응답, 429, 안전 차단이 섞여 오고, 모바일 연결이 끊기면 이미 생성된 응답이 사라졌습니다.
- **기획이 데이터 모델을 바꾼다.** 같은 스토리를 다시 플레이하는 재주행 기획이 들어왔는데, 기존 진행 기록은 완료 여부만 저장하고 있었습니다.

## 내 역할

대화 컨텍스트와 대화 기록의 기반 코드는 동료가 먼저 만들었습니다. 저는 그 위에 아래 기능을 만들었습니다.

- 캐릭터별 프롬프트 전략과 컨텍스트 조건 엔진
- 장기 대화 스냅샷
- 대화 분석 보고서 (서버 API와 Unity 화면)
- LLM API 실패 처리
- 재주행 회차 데이터 모델

「비정규직 황후」에서는 동료가 옮겨 온 조건 엔진 위에 다음을 더했습니다.

- 언어별 트리거
- 호감도별 지시문과 스토리 진행별 호칭
- 챕터 1~21의 설정 데이터: 대본에서 Gemini로 초안을 뽑고, Google Sheets에서 사람이 검수한 뒤 번역해 서버 데이터로 변환

## 핵심 결정

### 1. 컨텍스트는 벡터 검색이 아니라 명시적 조건으로 고른다

설정 항목마다 아래 조건을 둡니다.

- 매칭 키워드와 정규식
- 적용 스토리 구간 (시작·끝)
- 항상 포함 여부
- 쿨다운 턴
- 우선순위

매 턴 조건에 맞는 항목 가운데 **우선순위 상위 8개까지만** 프롬프트에 넣습니다. 스토리 구간 조건이 있어서, 플레이어가 아직 진행하지 않은 구간의 설정은 조건 단계에서 빠집니다.

이후 같은 구조에 다음 조건을 더했습니다.

- 배고픔·목마름 같은 캐릭터 상태
- 호감도 10 이상
- 시즌 이벤트
- 스토리 장면 종류

### 2. 긴 대화는 구조화된 스냅샷으로 압축한다

메시지 100개마다 Structured Output으로 다음 항목을 **원문 근거와 함께** 뽑아 OpenSearch에 저장합니다.

- 약속
- 사용자가 밝힌 정보
- 관계 변화

다음 대화에는 최근 기록 20개와 요약·스냅샷 이후의 메시지만 불러오고, 스냅샷은 대화 프롬프트와 분석 보고서에 함께 넣습니다.

### 3. 대화 분석 보고서는 스키마부터 정한다

1. 관계 지표와 베스트 모먼트 같은 보고서 구조를 Pydantic 스키마로 정의합니다.
2. Gemini `response_schema`와 OpenAI Structured Output으로 생성합니다.
3. 생성 결과를 OpenSearch에 저장하고, 생성·목록·상세 API를 만듭니다.
4. Unity에 목록·상세 화면을 붙입니다.

이후 호감도 반영, 대화 기록이 부족한 경우 처리, 보고서 언어 이탈 수정을 이어서 했고, 「비정규직 황후」로도 옮겼습니다.

### 4. 실패 유형마다 처리를 나눈다

| 실패 | 처리 |
| --- | --- |
| 빈 응답 | 스트림 최대 3회 재시도, 안전 차단 사유는 별도 분기 |
| 429 등 일시 오류 | 지수 백오프 1s×2ⁿ (상한 20s, jitter). 스트림은 첫 청크 전에만 재시도 |
| 재시도 대상 | 408·409·429·500·502·503·504·529만. 나머지는 바로 실패 |
| 금지 콘텐츠 판정 | 요약·스냅샷 저장을 건너뜀 |
| WebSocket 끊김 | 남은 스트림을 백그라운드에서 끝까지 받아 전체 응답을 저장 |

공급자는 Gemini·OpenAI·Anthropic 세 곳이고, 사용자가 게임 설정에서 대화 모델을 고릅니다.

### 5. 재주행: "회차"와 "영구"를 코드 전체에서 나눈다

진행 기록의 키를 `(user_id, story_id)`에서 `(user_id, story_id, round)`로 바꿨습니다. 0회차는 영구 기록이고, 가장 최근의 양수 회차가 현재 진행입니다.

그다음 진행 상태를 읽는 코드를 모두 찾아 성격별로 나눴습니다.

- 퀘스트 진행 판정 15곳: **회차** 기준
- 해금·다시보기·보상 24곳: **영구** 기준

보상이 두 번 지급되지 않게 막는 장치와, 회차가 바뀐 뒤 상태를 다시 조회하는 처리도 넣었습니다.

## 결과

- 대화 분석 보고서와 컨텍스트 조건은 두 게임 모두에, 장기 대화 스냅샷은 「멸망한 세계의 신이 되었다」에 들어갔습니다.
- 재주행
  - 회차 분리 테스트 5개가 통과했고, 오류를 일부러 넣은 두 조건에서는 실패하는 것을 확인했습니다.
  - 개발 DB 전체 사용자를 대조한 결과, 영구 기록 누락·추가와 최신 회차 불일치가 각각 0건이었습니다.

## 한계

- 컨텍스트 조건과 스냅샷이 응답 품질이나 토큰 사용량을 얼마나 바꿨는지는 측정하지 못했습니다.
- 실패 처리도 지연 시간이나 실패율을 전후로 측정한 기록은 없습니다.
