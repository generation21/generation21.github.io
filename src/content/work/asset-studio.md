## 배경

기획·아트팀이 게임의 캐릭터 이미지와 영상을 직접 생성하고, 결과를 히스토리로 관리하는 사내 도구입니다.

## 내 역할

저장소를 처음 만드는 것부터 웹 UI, 백엔드, 인프라 정의, GPU 워커, 운영 문서까지 혼자 맡았습니다.

## 구조

![React 웹이 JWT로 Azure Functions를 호출하고, Functions는 OpenAI·Gemini 이미지 API를 동기 호출하거나 Cosmos DB 큐에 작업을 등록한다. 사내 GPU 머신의 배치 워커가 켜져 있는 동안 2초마다 큐를 확인해 ComfyUI·vLLM으로 처리하고 결과를 Blob Storage에 올린다.](/image/work/asset-studio/architecture.svg)

웹과 API는 Azure에서 돌고, 생성은 사내 GPU에서 합니다. 인프라는 Bicep으로 정의했고, 인프라·코드·웹 배포 스크립트를 나눠 두었습니다.

## 핵심 결정

### 1. 생성 경로를 두 갈래로 둔다

작업마다 쓸 수 있는 백엔드를 설정으로 정합니다.

- **상용 이미지 API**: Function이 OpenAI·Gemini 이미지 API를 직접 호출합니다.
- **ComfyUI 워크플로**: 작업을 Cosmos DB 큐에 넣습니다.
  - 로컬 RTX 4090에서 필요할 때 켜는 ComfyUI 배치 워커가 큐의 작업을 처리합니다.
  - 워커는 켜져 있는 동안 2초마다 큐를 확인합니다.
  - 웹 화면에서 워커 상태를 볼 수 있습니다 (30초 간격 heartbeat).

### 2. 프롬프트는 LLM이 다듬고 번역한다

- 사용자가 게임·캐릭터·상황을 입력하면, LLM이 생성 모델에 맞는 프롬프트를 만들어 캐릭터 LoRA 워크플로로 넘깁니다.
- 영상 모델별로는 각 모델의 공식 가이드를 반영한 프롬프트 생성기를 따로 두었습니다.
- 입력한 프롬프트는 로컬 vLLM(Gemma)이 영어로 자동 번역합니다. 번역 작업도 같은 큐로 처리합니다.

### 3. 선택지가 실제로 동작하게 고친다

- **모델 선택**: 화면에서 어떤 모델을 골라도 같은 워크플로가 실행되고 있었습니다. (작업 × 모델) 표로 워크플로를 조회하도록 바꿨습니다.
- **자동 변형 생성**: 항상 10개씩 만들어 GPU 시간을 낭비하던 것을, 끄기·1·3·5개 중에서 고르게 했습니다.

### 4. 결과 저장의 일관성

작업은 큐에 들어가는데 결과 파일이 겹치거나 사라지는 문제가 있었습니다.

1. **진단**: Cosmos DB를 확인하며 큐 적재와 결과 저장을 나눠 봤고, 초 단위 타임스탬프 파일명이 충돌하는 것이 원인이었습니다.
2. **수정**
   - 파일명에 랜덤 접미사를 붙였습니다.
   - 워커가 한 번 정한 이름을 Blob 업로드와 히스토리 기록에 함께 쓰게 했습니다.
   - 아직 처리 중인 작업을 "완료"로 보여 주던 화면 표시도 "대기"로 바로잡았습니다.
3. **확인**: 같은 초에 파일명 500개를 생성하는 단위 테스트에서 중복이 0건이었습니다.

### 5. 운영과 인수인계

- 오래된 히스토리와 Blob 파일을 10일 보존 기준으로 정리하는 크론을 두었습니다.
- 설치·배포·일상 운영·문제 해결을 담은 README를 써서 인수인계했습니다.
